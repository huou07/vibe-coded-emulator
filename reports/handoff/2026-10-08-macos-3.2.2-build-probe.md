# macOS 3.2.2 package build probe

Date: 2026-10-08
Branch: `feature/phone-controller-cross-platform`
Source HEAD: `520582d8da26c5e0762fd9510808f1dd60b8cc5a`
Desktop app version: `3.2.2`

## Result

No new macOS DMG was produced. The standard `npm run build:macos` command
failed while compiling Rust procedural-macro dependencies, before Tauri could
create the app bundle. The same `mis-aligned LINKEDIT string pool` loader error
occurred with the installed Rust 1.98 and an isolated Rust 1.96 build.

The host is macOS 27.0 with Xcode 27.0 (build 27A266a). The project build sets
`MACOSX_DEPLOYMENT_TARGET=13.4`. The failed library reported LINKEDIT string
pool offset `0x002CE95C`, which is not 8-byte aligned. A Rust-generated probe
also failed to load through the host loader. A small dynamic-library probe
compiled with LLD loaded, but the real application dependency graph still
failed, so that is not a package workaround.

## External evidence

The Rust compiler issue
<https://github.com/rust-lang/rust/issues/157750> reproduces the same loader
failure on macOS 27 with deployment targets 12.0 and newer, and reports a
successful reproduction at 11.0. This matches the observed failure. Cargo's
separate host build configuration is currently nightly-only, so a clean local
retry must isolate the target directory and verify both the host tools and
the app's actual minimum OS before packaging.
